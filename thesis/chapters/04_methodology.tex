The evaluation code supports three prompt modes. \texttt{base\_native} is used for base checkpoints and leaves the benchmark prompt in its native flat form. \texttt{instruct\_templated} applies the model chat template to instruction-tuned models and is the default instruct setting. \texttt{instruct\_flat} feeds the same task text to an instruct model without chat templating and is used as a prompt-format diagnostic. These modes are implemented in the dataset classes and selected by \texttt{inference\_and\_generation.py}.

Deterministic evaluation uses temperature $=0$ and \texttt{n\_samples}$=1$. Stochastic pass@k evaluation uses temperature $=0.7$ and \texttt{n\_samples}$=16$, $64$, or $128$ depending on benchmark and run. For a problem with $n$ generated samples and $c$ correct samples, the unbiased pass@k estimator used by the repository is
\begin{equation}
    \mathrm{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}.
\end{equation}
The implementation is in \texttt{\detokenize{metrics/pass_k.py}} and the comparison script is \texttt{\detokenize{evaluate_pass_k.py}}.

\subsection{Task-Specific Answer Extraction and Validity Checking}
\label{sec:parser-details}
The parser layer is part of the experimental design. Different benchmarks require different validity checks, and the thesis results should be read together with these extraction rules.

\textbf{GSM8K.} The GSM8K dataset loader extracts gold answers from the official answer text using the \texttt{\#\#\#\#} final-answer marker and a numeric regular expression in \texttt{\detokenize{Parser.extract_answer_gsm8k}}.\footnote{Main files inspected: \texttt{\detokenize{dataset/gsm8k.py}}, \texttt{\detokenize{metrics/parsers.py}}, \texttt{\detokenize{inference_and_generation.py}}, and \texttt{\detokenize{evaluate_pass_k.py}}.} Generated answers in the main evaluator are extracted with \texttt{\detokenize{Parser.extract_answer_boxed}}, which takes the last \texttt{\detokenize{\boxed{...}}} or \texttt{\detokenize{\fbox{...}}} expression found in the model output. The extracted string is converted to a float when possible. The gold parser removes commas in official numeric answers; the boxed-output parser returns the boxed content and relies on float conversion for numeric normalization. In the main pass@k path, there is no final-number fallback for GSM8K model outputs. Correctness is computed by comparing the extracted value with the gold value, with numeric tolerance in \texttt{\detokenize{evaluate_pass_k.py}}.

\textbf{Countdown-cd4.} Countdown scoring uses the Dream-derived chained-equation metric in \texttt{\detokenize{dataset/countdown.py}}.\footnote{Main files inspected: \texttt{\detokenize{dataset/countdown.py}}, \texttt{\detokenize{inference_and_generation.py}}, and \texttt{\detokenize{evaluate_pass_k.py}}.} The main evaluator takes the first output line as the prediction and calls \texttt{\detokenize{cd_score_single}}. The scorer normalizes common operator variants such as \texttt{\detokenize{\times}}, \texttt{\detokenize{\cdot}}, \texttt{\detokenize{\div}}, and Unicode multiplication/division symbols. It then extracts leading comma-separated binary equations of the form \texttt{a op b = c}. Each left-hand expression is evaluated with restricted \texttt{eval}; malformed expressions are rejected. A multiset counter enforces that the supplied numbers are used exactly as allowed, intermediate results are introduced only by previous equations, and the final right-hand side equals the target. The allowed arithmetic operators are addition, subtraction, multiplication, and division in their normalized forms.

\textbf{Trip Planning.} Trip Planning scoring uses the Dream-derived parser in \texttt{\detokenize{dataset/trip_planning.py}}.\footnote{Main files inspected: \texttt{\detokenize{dataset/trip_planning.py}}, \texttt{\detokenize{inference_and_generation.py}}, and \texttt{\detokenize{evaluate_pass_k.py}}.} The parser scans the generated text for a total-day statement, visit day ranges, and flight lines of the form ``Day $d$ ... from City to City''. It reconstructs the ordered city sequence and stay lengths from the flight days. The scorer compares this parsed plan with the gold ordered city list and gold durations. It is a strict validity-style exact match over the required prefix: malformed plans parse to an empty list and therefore fail. Legacy JSON-style Trip Planning helpers exist in \texttt{\detokenize{utils.py}}, but they are not used by the main result JSONs analyzed here.

\subsection{Per-Question Correlation Protocol}
For each benchmark condition, the analysis computes a per-question accuracy vector for each model. Each vector entry is the fraction of samples for that question that were correct. Pearson correlations are then computed between model pairs. The canonical comparison uses 128 samples per model for GSM8K and Countdown, and 64 samples per model for Trip Planning. The HTML comparison files generated by \texttt{\detokenize{generate_comparison_html.py}} provide per-question inspection views for base and instruct settings.
